# STEP20 - 장애 대응 및 성능 테스트 보고서

## 📋 개요

콘서트 예약 시스템의 안정성과 성능 최적화를 위한 장애 대응 시나리오 및 성능 테스트 결과를 기록한 문서입니다.

**테스트 환경**:
- 부하 테스트 도구: K6
- 모니터링: Grafana + InfluxDB

## 📊 성능 테스트 결과

### 1. 카프카 도입 성능 테스트
📄 **상세 보고서**: [STEP20-1 카프카 성능 테스트](./STEP20_1_카프카성능테스트.md)

- ✅ **목표 달성**: P95 < 500ms 달성
- ✅ **안정성**: 실패율 < 5%
- 🔍 **개선점**: 예약/결제 단계의 응답시간 최적화

### 2. 인덱싱 성능 최적화
📄 **상세 보고서**: [STEP20-2 인덱싱 성능 테스트](./STEP20_2_인덱싱성능테스트.md)

- ✅ **쿼리 성능 개선**: 테이블 스캔 → 인덱스 스캔으로 성능 향상
- ✅ **DB 부하 감소**: CPU 사용률 현저히 감소
- 🔍 **개선점**: 인덱싱 미적용시 오래걸리는 요청 처리 완료

### 3. 캐시 성능 최적화
📄 **상세 보고서**: [STEP20-3 캐시 성능 테스트](./STEP20_3_캐시성능테스트.md)

- ✅ **평균 응답시간 대폭 개선**: 캐시 히트시 성능 향상
- ✅ **대부분 API 200ms 이내 응답**: 사용자 체감 성능 크게 개선
- ❌ **캐시 미스시 응답시간 증가**: 복잡한 쿼리 로직으로 인한 지연 발생
- 📝 **아쉬운 점**: Cache Miss Penalty 미해결, 시간 부족으로 근본적 코드 개선 미완료
